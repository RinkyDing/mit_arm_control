## 与旧测试程序的关键差异

| 旧测试模式 | 正式框架首版 |
| --- | --- |
| 脚本直接拥有控制器，构造时使能 | 服务拥有 CAN，构造只建立被动连接，arm + 初始有效目标才使能 |
| 测试脚本生成正弦速度 | 算法 SDK 提交完整七轴 MIT 目标，示例只在模拟环境运行 |
| 控制循环直接打印 | 有界日志队列、独立消费者，输出阻塞/关闭不会阻塞控制循环 |
| 当前反馈时间通常是应用处理时刻 | 实机使用内核接收时间戳估计反馈年龄，迟到的缓存帧不能当作新停止确认 |
| 主要检查反馈超时 | 检查算法 TTL、序号、完整轴集、机械软限位、速度/力矩/增益、变化率和温度 |
| 空载情况下异常退出 | 首版受支撑联调；不声称无支撑失能安全、不自动规划回桌 |
| 同脚本进程内退出 | 算法进程退出后控制服务仍可处理停止；控制服务自身被 SIGKILL 的情况必须依靠硬件与支撑 |

## 依赖与控制流

- `protocol` 是无 I/O 纯协议；`config` 是机器人配置；`safety` 是纯校验。
- `backend` 提供同形的 SocketCAN / SimBackend；两者构造都不会使能。
- `controller` 是唯一操作后端和修改电机状态的执行者，负责编排生命周期与定时通信。
- `ipc` 接收客户端请求，只交付有界动作/最新命令，不直接操作 CAN。
- `service` 先处理停止，再处理控制动作/目标和调度；轻量反馈快照与完整统计分开发布。
- `sdk` 只做本机协议与等待本次事务确认，不包含关节控制策略。

协议和安全约束不会因为算法选择更换而改变；实机配置也不写死在驱动里。故障、统计和周期日志均使用有界内存。

## 验证

命令：`PYTHONPATH=src python3 -m unittest discover -s tests -v`。

交付前完成 33 项离线/模拟集成测试：

- 23 项核心与生命周期用例：限幅、变化率、命令超时、零点与初始目标、漏收恢复、永久失联、发送队列满、停止未确认、日志阻塞、故障不能自动恢复等。
- 6 项真实子进程/Unix socket 模拟联调用例：单控制权与 observer、算法超时、算法进程被终止、服务 SIGTERM、SDK 示例及最终报告、终端输出管道堵塞时仍可通信和退出。
- 4 项 mock SocketCAN 用例：72 字节主机 FD 布局与 BRS、Linux 接收时间戳、参数回复分流、无效帧不能刷新反馈。

没有打开真实 CAN 或驱动电机，没有把模拟通过写成实机性能证明。模拟后端只是功能与故障注入模型，不是机械臂动力学模型。

## 上线前仍需完成的实际工作

1. 填写并核对完整七轴的 ID、方向、零姿态、关节限位、增益/力矩/变化率范围。
2. 确认支撑、急停与固件通信保护。模板故意缺失关键项，不能直接使能。
3. 按实际硬件版本验证归零、使能/失能回复及5M配置，确认对反馈温度和输出侧量纲的解释。
4. 算法在模拟后端接入并测试命令 TTL 与停止；实机首次使用受支撑小范围运动。
5. 实测七轴吞吐量、迟到分位数、最大反馈年龄与内核/USB行为。当前 VMware 和 Python 环境不保证硬实时。

停止反馈只证明收到失能状态，不证明电机静止。发送成功只说明内核接受，不证明电机执行。内核时间戳也不是电机内部采样时间。未提供多圈展开、碰撞避免、重力保持、无支撑故障回桌、系统级实时优先级或控制服务 SIGKILL 后的软件停止保证。

## 自动读取量程更新

arm 逐轴读取实际 PMAX/VMAX/TMAX，全组验证通过后，后端编码和解码统一采用本轮读数。型号默认表和配置文件不变，机械限制不自动调整。实机离线 readiness 仅检查不依赖真实量程的部分，量程兼容性延迟至 arm。状态快照新增 protocol_ranges。读取失败、非法读数和限制超量程会停止，旧反馈缓存在量程切换后清除。

新增 8 项量程测试，含每轴独立、配置/寄存器不被覆盖、非法值、读取失败、超量程限制、重读、编解码与 mock SocketCAN；连同既有用例共 42 项通过。未访问实机 CAN。
